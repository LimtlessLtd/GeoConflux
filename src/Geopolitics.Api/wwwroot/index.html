What this is

GeoConflux is a .NET 10 event-processing platform. Heterogeneous observations — news wires, satellite thermal detections, structured event records, manual submissions — are ingested asynchronously, deduplicated, geolocated deterministically, and correlated into incidents.

The core idea

An observation is not an incident. Several sources describing one event produce a single incident with several pieces of linked evidence. Duplicate evidence is linked and kept, never deleted, so provenance survives.

Pipeline

source → validate → queue → normalise
     → deduplicate → resolve location
     → correlate → persist → publish

What is actually running

No AI or ML model is used yet. Categories and severities come from a deterministic keyword classifier. The AI enrichment stage is designed and has an interface waiting for it, but it is not built, so nothing here is a model output.

Rules the pipeline enforces

  • Only a deterministic resolver may produce coordinates. An unmappable report stays visibly unplaced rather than being given plausible-looking ones. This is a standing constraint on the AI stage that comes later, so it can name a place but never place it.
  • Realtime messages are published only after state is committed, so a client can always recover by re-querying.
  • A failed geocode or correlation retains the source payload with a reason instead of discarding evidence.
  • A re-delivered report is recorded as a duplicate rather than deleted, so the fact that a source repeated itself stays auditable.
