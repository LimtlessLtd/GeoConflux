What this is

GeoConflux is a .NET 10 event-processing platform. Heterogeneous observations — news wires, satellite thermal detections, structured event records, manual submissions — are ingested asynchronously, deduplicated, geolocated deterministically, and correlated into incidents.

The core idea

An observation is not an incident. Several sources describing one event produce a single incident with several pieces of linked evidence. Duplicate evidence is linked and kept, never deleted, so provenance survives.

Pipeline

source → validate → queue → normalise
     → deduplicate → resolve location
     → correlate → persist → publish

What is actually running

Every observation passes through an AI enrichment stage that translates, summarises, classifies, assesses severity, extracts named actors, and names a place. Its response is validated against a versioned schema before anything is adopted.

The provider is configurable. With none configured — which is the default, and what the published snapshot was built with — enrichment runs against a deterministic in-process stand-in: a keyword classifier and a script-based language detector. It is labelled ai:Mock/deterministic-stub wherever it appears, and it is not a language model. Point the application at Ollama, OpenAI, or Azure OpenAI and the same pipeline uses that instead.

Every classification on this page carries the confidence and the method that produced it. When the enrichment stage is unavailable, times out, or returns output that fails validation, the keyword classification is kept and the failure is recorded rather than hidden.

The severity model

A conventional multiclass logistic-regression model (ML.NET, SDCA maximum entropy) is trained in-process from a labelled corpus of 140 synthetic reports and scores every observation the pipeline accepts. It sees the report text, the assigned category, and four features a bag of words cannot: how many sources support it, how confident the classification was, how many actors were named, and whether it could be placed.

It is a second opinion and never an authority. The severity an incident is stored and displayed with is the one the pipeline acted on; the model's prediction is recorded next to it, and where the two differ the evidence list says so. A model fitted to a small synthetic corpus has no business overruling a source that declared its own severity.

It is evaluated on 45 held-out cases it was never trained on, against the same labels and against the enrichment path run over the identical cases — so the two are comparable rather than merely both present. The measured figures, the per-class breakdown, and every case where the two disagreed are published in the repository, along with what those numbers do and do not support.

The activity score

The Analytics tab reports a Geopolitical Activity Score for each window. It is an openly documented heuristic, not a risk assessment: every incident contributes severity × recency × corroboration × confidence, the total is divided by the window length to give a rate, and that rate is mapped onto 0–100 by a saturating curve. The formula, the per-factor breakdown, and the raw rate are all shown next to the number, because a score a reader cannot take apart is a score they have to take on trust.

It summarises what this system ingested. A quiet score can mean a quiet period, or it can mean no adapter was configured and nothing arrived — those are different facts and the score cannot tell them apart.

Rules the pipeline enforces

  • Only a deterministic resolver may produce coordinates. The enrichment schema has no latitude or longitude field at all, so a model can name a place but can never place it. An unmappable report stays visibly unplaced rather than being given plausible-looking coordinates.
  • Realtime messages are published only after state is committed, so a client can always recover by re-querying.
  • A failed geocode or correlation retains the source payload with a reason instead of discarding evidence.
  • A re-delivered report is recorded as a duplicate rather than deleted, so the fact that a source repeated itself stays auditable.

Basemap

Imagery and boundaries come from Esri's public map services, which serve detail to roughly street level without an API key — so the globe stays useful while the project keeps its "runs with no credentials" property. Use the Basemap control to switch between satellite, street, and topographic views. If the tile service cannot be reached the globe falls back to the coarse texture bundled with CesiumJS and says so.

Clicking an incident frames it regionally rather than zooming to street level. Most incidents sit at a gazetteer centroid for a named area, so a closer camera would imply a precision the data does not have. Zoom in yourself if you want it.

Place names

Nothing here writes a coordinate. A report is drawn exactly as precisely as the place lexicon can place it, and that lexicon is extracted from published databases rather than typed from anybody's recollection — which is the only reason its coordinates can be trusted.

Administrative units worldwide and the towns that are their seats come from GeoNames, used under CC BY 4.0 and filtered to the languages that actually report conflict. Settlement-level names inside the theatres under active tasking come from Wikidata, which is CC0. The Coverage tab states how many names the lexicon holds per country, because that figure is the ceiling on what any text report from there can ever place.
